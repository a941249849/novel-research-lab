# 02：系统缺失与弱化能力差距分析报告 (Missing Capabilities Gap)

*   **当前阶段**：`Phase 0C`
*   **分析定位**：系统设计 Gap 审计

为了看清 v1.0 MVA 架构在“复杂度收敛”过程中的妥协，本文件对原始愿景中 15 个子系统的缺失与简化进行深度差距分析，为后续 v1.5 与 v2.0 升级保留技术锚点。

---

## 1. 知识库与设定体系 (Bibles & Worlds Gaps)

1.  **Story Bible (故事圣经)**：
    *   *差距*：v1.0 仅将故事大背景和核心主线用几百字纯文本（Book DNA）描述。缺失了时间树分支、卷首备忘录、剧情里程碑网络的结构化定义。
2.  **Character Bible (人物志)**：
    *   *差距*：v1.0 的人物被弱化为 State Ledger 中一个扁平的 `true_profile` 节点（包含姓名、等级、性格权重）。缺失了角色人际关系网（Graph）、动态心理状态演变线、马甲防火墙（多身份隔离）等防穿帮设计。
3.  **World Bible (世界百科设定)**：
    *   *差距*：v1.0 仅定义了名义上的境界名称序列。缺失了宗门地理大沙盘、功法属性互克克制法则、地方天道法则覆盖范围的精确建模。
4.  **Faction System (阵营管理)**：
    *   *差距*：v1.0 中阵营仅仅是一个扁平的声望数值映射表（如：`"野荒猎人": -45`）。缺失了阵营势力冲突模型、资源领地抢夺逻辑、以及声望增减触发阵营追杀事件的动态系统。
5.  **Power System Manager (战力平衡器)**：
    *   *差距*：v1.0 仅使用数值 `combat_power` 简单标记战力。缺失了防御战力崩塌的“越级系数缩放指数”、“法宝战斗贡献加权算法”与“群体乱战合力衰减模型”。

---

## 2. 状态账本与长期记忆 (Memory & Ledger Gaps)

6.  **Long-term Memory (长期记忆层)**：
    *   *差距*：v1.0 **完全被剥离**。没有向量数据库检索（RAG），没有情节图谱（Graph）。仅依赖在 LLM 提示词中强灌前文大纲和骨架，随着字数增长，极易发生前文忘却和废设堆积。
7.  **Foreshadowing Ledger (伏笔控制账本)**：
    *   *差距*：v1.0 **完全被剥离**。大纲生成时无法登记“草蛇灰线”，无法跟踪一个秘密何时被谁埋下、必须在第几章内通过什么事件收回。

---

## 3. 生成、修改与文笔控制 (Generation & Style Gaps)

8.  **Chapter Generation Loop (多章节滚动生成)**：
    *   *差距*：v1.0 被限制在“仅生成第一章 Demo 正文”。缺失了长篇大纲滚动生成、上一章正文 $\rightarrow$ 提取运行后 Ledger 状态 $\rightarrow$ 继承状态生成下一章的滚动迭代主循环。
9.  **Revision Loop (多轮修改环路)**：
    *   *差距*：v1.0 为 Single-shot Prompt 生成，大模型一次性吐出正文，无“智能体自我批判-草稿修改-段落抛光”机制。
10. **Continuity Checker (时空与情节连续性校验)**：
    *   *差距*：v1.0 校验器（`DoubleTrackLedgerValidator`）仅能通过 Schema 限制做静态规则强校验（如检测法宝副作用是否在大纲中说明）。缺失了基于时序逻辑（Temporal Logic）的情节冲突检查（如死人复活、瞬间跨越百万里等时空冲突）。
11. **Style Control (文笔风格微调器)**：
    *   *差距*：v1.0 仅依靠在 Prompt 中注入负向命名红线与禁止模式进行字面硬过滤。缺失了文风 Embedding 相似度匹配、风格分词概率调整、以及句式长度分布（Sentence Length Distribution）控制系统。

---

## 4. 编排、实施与执行层 (Orchestration & Engineering Gaps)

12. **Agent Orchestration (异步智能体编排)**：
    *   *差距*：v1.0 的执行管道是一个线性的 Python 脚本过程。缺失了高并发的多 Agent 异步消息总线（MQ）及容错重试控制器。
13. **Human Review Gate (人工干预网关)**：
    *   *差距*：v1.0 中人工审查仅靠命令行中断与配置文件手动确认。缺失了可视化的设定-正文交互编辑看板（UI）、以及大纲分支选择交互网关。
14. **Codex Engineering Pipeline (工程流水线落实力度)**：
    *   *差距*：在 Phase 0B/0C 研究阶段，所有动作均由 Antigravity 强行代理。Codex 本地自动提取脚本、全量切片清洗工具链在工程层尚未真正完全编码落地。
15. **Hermes Creative Layer (文学消费层落地程度)**：
    *   *差距*：Hermes 目前仅被规划在文档中，尚未编写成为独立的“玄幻内容创作者”客户端，导致目前的 Demo 生成仍属于高度人工脚手架辅助状态。
