# Phase 2D Outline Tree Requirements

## A. Outline Tree Goal

The future Outline Tree should convert the accepted Story Bible into a write-ready first-volume structure while still avoiding prose generation.

This entry file does not generate the Outline Tree itself.

## B. Required First Volume Functions

The future first-volume structure must be designed to carry these functions:

- Establish the protagonist's half-life identity.
- Establish the mother's life-debt countdown.
- Establish the poor city's wrong account.
- Establish the initial pressure from the life-registry office, life vault, and debt collectors.
- Show the first use of life-account ability.
- Show the first bodily backlash.
- Show the first public reversal satisfaction point.
- Open the map edge toward the prefecture or higher life vault.
- Leave a world ancient-debt hook.

## C. Problems To Prevent

The future Outline Tree must prevent:

- Turning into "one account investigation per volume."
- Turning into an audit-procedure story.
- Writing only setting explanation.
- Expanding the heavenly total ledger too early.
- Expanding the outer debtors too early.
- Resolving the mother's life debt too early.
- Making the protagonist a no-cost solution engine.
- Weakening the poor-city small community.

## D. Future Output Granularity

Future Phase 2D output may include:

- First volume core thesis
- First volume main conflict
- First volume staged satisfaction chain
- First volume map progression
- First volume character function slots
- First volume foreshadowing chain
- First volume state-ledger seeds
- Chapter cluster / arc cluster

Future Phase 2D output must not include:

- Novel prose
- First chapter
- Detailed chapter-by-chapter prose-level outline
- Dialogue
- Scene drafts
- Complete character cards

## Boundary Confirmation

These requirements define what the future Outline Tree must solve. They do not solve it here.
