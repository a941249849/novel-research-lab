# 04：系统功能研发路线图与版本划分 (Roadmap)

*   **当前阶段**：`Phase 0C`
*   **规划周期**：v1.0 $\rightarrow$ v1.5 $\rightarrow$ v2.0

## 2. 研发版本决策依据

### v1.0 必须实现 (最小可行闭环 MVA)
*   *包含模块*：扁平设定（Book DNA）、双轨属性与声望表（State Ledger）、静态校验（Validator）、单章节正文生成（Generator）、LCS 预警审计（Auditor）、本地 CLI 管道。
*   *决策原因*：必须优先验证“机制读入 $\rightarrow$ 状态记账 $\rightarrow$ 原创正文 $\rightarrow$ 相似审计”这一“读-转-写”极简链路，确保工程架构能完整闭环且数据结构稳定。

### v1.5 增强实现 (分析与多轮交互)
*   *包含模块*：分层故事百科、动态关系网络、战力倍率公式、伏笔标记追踪、Draft-Critic 修改环路、文笔匹配引擎。
*   *决策原因*：引入多智能体博弈（写作与修改）和文笔细化控制，真正提升生成小说的“可读性”与“情节连贯度”，属于由闭环向质量提升过渡的阶段。

### v2.0 长篇生产系统 (工业级产出)
*   *包含模块*：大长篇自动大纲计划引擎、向量长期记忆、异步代理消息队列总线、可视化交互 Dashboard 创作软件。
*   *决策原因*：支持十万字以上甚至百万字长篇的多轮、多批次生产与交互编辑，解决 LLM 的长周期遗忘缺陷，属于真正的生产力工具。

### 暂不实现 (过度设计)
*   *包含模块*：编译器级底层天道法则解析引擎。
*   *决策原因*：网络小说创作重在情节张力和情绪反馈，强行用语法解析器去编译“天道法则”属于重度研发的学术游戏，无商业与工程产出价值。
