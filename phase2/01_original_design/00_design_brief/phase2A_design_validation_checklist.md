# Phase 2A Design Validation Checklist

Use this checklist to review future Hermes original project candidates.

## Mechanism Use

- [ ] Candidate uses explicit mechanism IDs.
- [ ] Candidate uses mechanisms from at least 3 different Core7 books.
- [ ] Candidate does not move one source book's mechanism set as a group.
- [ ] Candidate distinguishes main, auxiliary, and constraint mechanisms.
- [ ] Candidate maps selected mechanisms to BookDNA / NarrativeDNA / StateLedger.

## Original Transformation

- [ ] Appearance transformation is documented.
- [ ] Causal transformation is documented.
- [ ] Cost or backlash transformation is documented.
- [ ] Social-structure transformation is documented.
- [ ] Emotional-feedback transformation is documented.

## Source-Risk Check

- [ ] No source proper nouns appear.
- [ ] No source artifact names appear.
- [ ] No source organization names appear.
- [ ] No source level names appear.
- [ ] No source protagonist path is copied.
- [ ] No source plot sequence is reproduced.
- [ ] No bridge or scene is retold from a source book.

## Stage Boundary

- [ ] Candidate does not write prose.
- [ ] Candidate does not write a first chapter.
- [ ] Candidate does not include dialogue.
- [ ] Candidate does not include concrete scene description.
- [ ] Candidate does not exceed setting, mechanism, and structure level.
- [ ] Candidate does not start 18-book full extraction.
- [ ] Candidate does not treat 11 stub books as formal assets.

## System Alignment

- [ ] Candidate is consistent with `system_master_spec_v0.1.md`.
- [ ] Candidate can be reviewed by Antigravity before any creative production.
- [ ] Candidate can later be converted into BookDNA.
- [ ] Candidate can later be converted into NarrativeDNA.
- [ ] Candidate can later be converted into StateLedger.
- [ ] Candidate includes originality risk notes.
- [ ] Candidate explains why it is not a copy of source books.

## Decision

- [ ] PASS
- [ ] PASS WITH FIXES
- [ ] FAIL
