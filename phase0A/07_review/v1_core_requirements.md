# Novel Research Lab v1.0 核心功能需求书 (v1 Core Requirements)

本规划书明确了 Novel Research Lab v1.0 必须保留的核心工程能力。一切设计围绕唯一核心目标：**稳定跑通从“读入小说 -> 机制校准 -> 原创转化 -> 生成合格的原创第一章正文”这一极简闭环**。

---

## 1. 核心业务闭环：“读-转-写”极简通路
v1.0 系统必须以无分支线性管道方式跑通以下流程：

```mermaid
graph LR
    Read["读入小说<br/>(骨架扫描+特征提取)"] --> Transform["原创转化<br/>(五步脱敏工作流)"]
    Transform --> Write["大纲与文本生成<br/>(原创第1章正文)"]
```

-   **读入端**：支持以 `scan_novels.py` 为基础的文本提取，自动生成包含字数、章节数、编码、SHA-256 和估计流派分类的 Manifest 基础文件。
*   **转化端**：实现静态的“原创转化规则映射器”，能根据 `signature_feature_matrix.json` 中配置的机制进行命名替换与因果归因重写。
-   **写入端**：基于转化后的大纲和角色设定，稳定输出具有合格中文网文文笔（支持设置黄金三章 Hook、伏笔预埋）的**第一章原创正文**（3000-5000字）。

---

## 2. 基础数据架构的精简标准
放弃所有高维动态计算，v1.0 仅对以下基础字段进行结构化静态追踪：

### ① Book DNA v1.0
-   `level_system`：简单的线性境界数组（如：练气、筑基、结丹），每个境界绑定最大寿命与基础灵力上限。
-   `resource_constraints`：核心升级道具列表（如异火、特定丹药），定义其稀缺度与升级关联。
-   `world_lore`：世界观核心背景段落、公共语汇表。

### ② Narrative DNA v1.0
-   `plot_checkpoints`：主要剧情里程碑列表（如：退婚事件、决决云岚宗、换图降维）。
-   `tension_tracker`：情绪抑扬状态追踪器。仅用简单的整型数值（-10 到 +10）来表征某一节点的憋屈度（负值）或爽感释放度（正值），计算黄金累积比例，不再使用复杂的生理情绪模型。

### ③ State Ledger v1.0
-   `actor_attributes`：主角的主武力数值、副职业等级。
-   `inventory`：主角的法宝、丹药资产静态列表。
-   `dual_track_identity`：主角的双轨身份状态表。仅需包含两组静态映射：
    -   `true_profile`：真实修为、真实姓名。
    -   `public_mask`：显示修为（掩码）、假名/易容马甲。
    -   *叙事引擎通过简单比对 True 与 Public 之间的数值差，若差值较大则自动触发“扮猪吃虎”或“雷霆反杀”的情节模板*。

---

## 3. 最低限度原创防剽窃过滤机制
-   **词汇防火墙**：在生成第一章正文时，系统必须自动比对敏感词库，拦截并自动替换任何来自于原著的特定功法名（如《焚决》、《扮演法》）、角色名（如叶凡、韩立）与名场面特定术语。
-   **因果链转换验证**：系统在大纲生成阶段必须检查，原著中由“不可直接复刻内容”触发的事件（如韩立的小绿瓶催熟），必须在原创大纲中被完全赋予新的动力学归因（如主角的古代科技冷凝器）。
