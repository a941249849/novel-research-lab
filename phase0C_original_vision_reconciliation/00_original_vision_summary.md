# 00：小说研究与长篇创作系统原始愿景回顾 (Original Vision Summary)

*   **项目定位**：`Novel Research Lab` 原始系统愿景与立项构想回顾
*   **归档时间**：2026-07-08

---

## 1. 系统原始目标 (Original Goals)

Novel Research Lab 立项的最初目标，是构建一个集**“经典语料深度研究”**与**“原创长篇小说生成”**于一体的工业级 AI 辅助创作系统。其核心工程愿景可概括为：
1.  **叙事机制提炼母机**：能够自动化读取、采样、切片分析百万字以上的网络经典小说，结构化提炼其核心爽点、情节模型、战力等级与关键矛盾机制。
2.  **原创脱敏与版权安全**：通过“机制剥离-功能替换-重新命名-世界观归因”的原创性工作流，使系统能合法合规地复用经典作品的深层叙事张力，同时规避换皮与低级抄袭风险。
3.  **长篇连贯性控制**：支持大纲-细纲-正文的自顶向下逐步展开，通过“状态账本”和“记忆环路”彻底解决大语言模型在长篇创作中常见的遗忘、前后矛盾、战力崩塌等硬性顽疾。

---

## 2. 借鉴的开源与社区能力 (Borrowed Capabilities)

本系统的核心模块设计广泛吸收了 GitHub 社区、学术界及工业界在长篇小说写作与 AI 编排方案上的前沿研究成果：
*   **Story Bible / World Building**：借鉴了社区中关于“故事圣经（Story Bible）”的层次化设计，将小说设定拆分为角色、世界法则、阵营关系三套独立的知识载体。
*   **长篇写作细化细纲规划**：借鉴了“树状细纲网（Tree of Outlines）”及“递归情节展开（Recursive Plot Expansion）”的思路，实现从几百字大纲到几十万字细纲的平滑延展。
*   **叙事状态管理系统**：吸取了游戏设计中“状态机（State Machine）”与“双轨属性账本（True/Public Ledger）”的概念，用于精确管理主角在漫长升级过程中的真实底牌与公开掩码。
*   **智能体编排与审校环路 (Critic-Loop)**：参考了“草稿-审校-改写（Draft-Review-Rewrite）”三段式闭环写作代理方案，保证小说文笔风格和逻辑的稳定性。

## 3. 原始设想中的核心模块 (Original Architecture Design)

原始设想中，系统是一个由 15 个子系统及核心层组成的庞大矩阵：
1.  **Story/Character/World Bible (圣经系统)**：管理核心故事背景、人物小传与世界底层物理化学法则。
2.  **Faction & Power System Manager (阵营与战力管理)**：动态跟踪各大宗门声望，控制主角越级战斗的胜率数学模型。
3.  **Long-term Memory (长期记忆层)**：基于向量检索与本地文件存储的长期事件缓存。
4.  **Foreshadowing Ledger (伏笔/线索控制账本)**：登记已埋下的伏笔，在大纲合适章节强行触发收回动作。
5.  **Chapter Generation & Revision Loop (正文生成与修改环路)**：智能体多轮协作的写作与润色系统。
6.  **Continuity & Style Control (连贯性与文笔控制)**：监控正文是否违背账本设定，并对词汇风格（如修仙白描风格、诡秘维多利亚翻译风）做强约束。
7.  **Orchestration & Review Gate (编排与人工审查门)**：控制执行流水线，并在关键节点挂起等待人类作者修改决策。
8.  **Codex & Hermes Layers (工分层)**：Codex 专责提取、重构与管道代码自动化；Hermes 专责文学知识消费与创意内容写作。

---

## 4. 原始设想中的工程执行方式 (Original Execution Model)

在最初的设想中，系统并非由单一的大型 Agent 依靠 Context Window 强行处理所有事务，而是：
*   **本地 CLI 脚步化驱动**：主控制程序通过命令行（Python/AGY SDK）触发，将提取、映射、大纲生成、正文合成各阶段拆分为可独立运行的、幂等的本地脚本。
*   **多智能体异步管道 (Asynchronous Agent Pipelines)**：Reader, Transformer, Writer, Auditor 作为独立的子 Agent 服务异步挂载在流水线上，通过本地文件进行状态中转。
*   **增量式状态存储**：所有的设定、大纲、正文与状态均采用轻量化本地文件（CSV/JSON/TXT）作为数据库，随时支持人工版本控制（Git）与断点续传。
