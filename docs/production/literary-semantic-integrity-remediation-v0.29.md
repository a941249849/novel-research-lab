# NRL 文学语义完整性整改 v0.29

## 问题定义

v0.18 已证明十八本语料的连续全文分块、单书综合、输入哈希与跨书输出在结构上完整，但原验证只约束数组非空、引用合法和输入绑定，不能证明：

1. 每本书最有辨识度的长篇机制被保留；
2. 单书独有机制不会因“至少两本书支持”而被跨书抽象丢弃；
3. 人物高光、成长阈值、地图扩张、历史载体和高潮汇流被单独审计；
4. 项目明确记录了每项重要机制的采用、原创转化、延后或拒绝；
5. 项目生产门禁会因文学语义合同缺失或漂移而关闭。

## 双通道蒸馏

### 跨书共性通道

保留由两本及以上作品共同支持的抽象机制，用于识别可迁移的长篇规律。

### 单书标志性通道

每本书建立不可被跨书压缩替代的 signature profile，覆盖十二个维度：

1. 叙事主脊；
2. 人物高光架构；
3. 成长与阈值；
4. 地图与尺度扩张；
5. 历史、神话或书中书载体；
6. 势力与资源博弈；
7. 情感关系与代价；
8. 伏笔与兑现；
9. 高潮汇流；
10. 读者反馈节奏；
11. 文风与生命力；
12. 失败模式与负面经验。

维度可以标记为 `explicit`、`implicit` 或 `not_dominant`，但不得缺失。`not_dominant` 必须说明这本书依靠什么替代机制维持长篇生命力。

## 项目应用合同

项目必须对全部十二个维度和所有被选中的 signature mechanism 给出：

- `adopt`：采用其抽象功能；
- `transform`：经原创因果重写后采用；
- `defer`：当前卷不使用，但保留到指定阶段；
- `reject`：因项目身份、原创风险或平台风险拒绝。

不得只写“已参考”。每个采用项必须绑定项目 canonical artifact 和原创转换说明。

十八本书的十二维单元格必须全部登记，共 216 项。未启用项的状态是
`protected_deferred`，不是“已吸收”：它必须保留当前 source finding 摘要、
项目不启用原因和重新启用条件。运行时启用清单只允许 `transform`、`adopt`
或 `reject`，且必须与 216 项处置中的非 `defer` 集合完全一致；重复、未知、
冲突或隐式启用一律失败。

## 《百工夜行录》专项整改

在正式正文继续前新增并冻结：

- `character_highlight_matrix.v1.json`：十五卷五人主体性与不可替代高光；
- `world_progression_atlas.v1.json`：十五卷地域尺度、进入条件、规则变化，以及六能力四岗位权限谱；
- `embedded_history_engine.v1.json`：十五则“百工旧账”，作为情节证据、历史争议和现实决策发动机；
- `literary_semantic_application.v1.json`：从十八本 signature profiles 到本项目的采用/转化/拒绝记录。

“百工旧账”只迁移“历史副线参与现实主线”的抽象功能，不复制《人祖传》的人格化蛊虫、寓言句式、概念角色、事件顺序或价值命题。

## 门禁

- 文学语义验证未通过时，项目不得为 `production_ready`；
- 任一语义来源、项目合同或应用清单漂移后，旧 baseline 和旧双审授权自动失效；
- baseline 同时绑定文学语义运行时、章节生产运行时、模型路由和审读 Schema，
  防止授权后仅修改代码绕过门禁；
- 初稿、修订生成、修订摄取和章节接受都必须重新检查实时 Owner 授权与
  hash-bound semantic context；
- 每章初审与终审均须提供非空的 `semantic_realization`、
  `progression_permissions`、`history_coherence` 证据；模型直连和外部文件
  摄取共用同一校验器；
- 卷一历史合同不得引用卷二至卷十五的 dossier；
- v0.29 以前未绑定项目、baseline 和禁止范围的旧授权全部失效；
- 正文授权按卷内已声明的十章窗口动态计算；每个窗口必须单独绑定
  baseline、双审哈希、窗口外禁止范围和到期 mission，不能把系统写死在第 1–10 章；
- 正式正文登记表必须保持为空，直到新 baseline 完成独立双审和新的 Owner 授权。
